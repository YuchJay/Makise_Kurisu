# 开发、交付与文档维护流程

适用于本个人项目，自 2026-11-08 文档基线起使用。流程应服务实际任务，
小修改只更新受影响条目，不要求每次重写所有文档。

## 1. 接续工作

1. 读 `docs/STATUS.md` 和 `docs/TRACKER.md`，确认当前版本、待验收事项和用户最近要求。
2. 查看 Git 状态，识别尚未提交的 0.9.0 实现；不能重置、覆盖或混入无关更改。
3. 按任务关联需求编号；新增问题登记 B 编号，重大选择登记 D 编号。
4. 说明本阶段准备完成什么，优先处理当前交付的阻碍。

基线中未完成的首次授权，应继续 T-001，不能因为日期变化就默认授权已经完成。

## 2. 实施变更

| 变更类型 | 最小记录与约束 |
|---|---|
| 文案 / 普通工具 | 需求、相关台词/界面、版本说明；不动输入组件 |
| 人物 / 动画素材 | 保留源图、处理脚本、批准版本与同尺度预览；按用户要求先审后接入 |
| 输入过滤 / 权限 / 协议 | 关联 T-001～T-004，说明组件是否重建及是否可能再次授权 |
| 数据结构 / 持久化 | 说明兼容性、失败处理和现有数据保护 |
| 目录清理 | 列明删除类型、保留当前应用和已批准素材，避免清掉组件身份 |
| 纯文档 | 校对源码及 Git 基线，不递增产品版本、不触发应用重建 |

不要为了文档同步改动应用行为。不要存入 API 密钥、实际输入文本、个人剪贴板内容、
系统权限数据库或本机用户数据。运行不需要历史生图密钥。

## 3. 证据与验收

- 用户没有要求测试或验证实现时，不擅自新增或运行测试；构建和测试分别报告。
- 需要现场验收时，从 ACCEPTANCE 选择与变更有关的步骤，经用户安排执行。
- 构建成功只写构建成功；“已启动”只证明进程启动；用户操作结果才关闭相应验收。
- 界面不可见、系统锁屏或缺权限时，记录具体限制，继续可做的代码/文档工作。
- 修改系统权限仍由用户实际确认，不能用脚本绕过系统授权。
- 用户反馈变化后及时更新验收记录，而不是仅把 PROGRESS 写成“修好了”。

## 4. 结项与提交

1. 更新 STATUS 的版本、阶段、未完成范围和最近提交。
2. 更新 TRACKER 的任务状态、缺陷复验；有未验收项则如实保留。
3. 在 PROGRESS 追加本次事实，更新对应 `releases/` 说明。
4. 用户要求提交时，核对完整差异和新文件，确认 .gitignore 排除了本地产物。
5. 提交所有属于本次目标的源码、正式素材、脚本和文档，不提交 outputs/work。
6. 依既有用户偏好调用 `proxy` 后推送；成功输出后才能写“已推送”。
7. 记录提交哈希、分支、推送结果。失败时保留本地提交，说明实际错误。

复用现有 origin/main，不擅自强推、重写历史、打发行标签或创建公开发布。
若用户明确授权带已知未完成项交付，应在版本说明中列出这些范围。

## 5. 文件布局

```text
KurisuDesktop/
  Sources/           主应用
  InputAgent/        固定监听小应用与过滤器
  Shared/            本机 IPC 协议
  Resources/         正式运行素材
assets/source/       用户确认的源图、提示词及处理来源
scripts/             构建与素材处理
docs/                维护源文档
  releases/          按版本使用说明
outputs/             当前应用、预览和交付快照（忽略）
work/                临时文件、可再生缓存、历史归档（忽略）
```

清理时可以删除可再生的 `work/build`、Python 缓存及过时临时图；
不要把 `work/archive` 当垃圾自动清空。保留 `outputs/Kurisu.app` 内嵌的签名监听组件，
才能在普通重建时直接复用。不能把删除整个导出应用描述为“不会影响授权”。

## 6. 文档更新映射

| 发生的变化 | 必须更新 |
|---|---|
| 任务完成 / 新问题 | TRACKER；必要时 ACCEPTANCE |
| 版本、提交、交付状态 | STATUS、README、PROGRESS、对应版本说明 |
| 动画参数 / 交互 | DESIGN；若有关素材则 ASSETS |
| 权限 / 组件 / 数据流程 | ARCHITECTURE、INPUT_AGENT |
| 产品范围或用户新决定 | PRODUCT、DECISIONS、TRACKER |
| 本套快照交付 | 重新导出 outputs/project-documentation 及压缩包 |
