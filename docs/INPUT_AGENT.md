# 固定输入监听组件

## 职责与授权

- 桌宠主应用 `local.kurisu.desktop` 展示动画与工具，不再直接申请输入监控权限。
- 独立应用 `local.kurisu.inputagent`（系统显示“Kurisu 输入监听”）负责权限申请、
  被动事件监听、严格打字过滤与安全输入检测。
- 监听组件通过 Launch Services 启动，不作为桌宠的普通命令行子进程启动。
- 固定安装位置：
  `~/Library/Application Support/KurisuDesktop/InputAgent/KurisuInputAgent.app`。
- 首次点击“我授权，开启打字响应”后，由监听组件调用系统授权接口。
  用户在系统中确认后，客户端自动刷新连接；返回桌宠时可重启组件刷新权限状态。
- 主应用旧授权不会迁移给新组件。首次仍需系统确认，不代替用户点击系统开关。
- 如果系统未自动加入列表，设置页提供一次性手动定位、添加的折叠说明。

## 构建身份

`scripts/build_input_agent.sh` 单独计算监听源码、组件 Info.plist、共享 IPC
协议及构建脚本的 SHA-256 指纹，写入 `InputAgentBuildID`。

已有内嵌组件的指纹匹配且签名有效时，构建直接复用它，不重复编译或签名。
因此普通桌宠功能更新不会改变组件可执行文件哈希。安装时再次核对组件签名、
元信息与可执行文件 SHA-256，相同的固定组件保持原样。

组件需要更新时，在同一目录先暂存新副本，确认旧组件退出，再替换；替换失败
则尽力恢复旧副本。组件自身代码更新仍可能使临时签名的身份变化，需要再次授权。
完整清理导出包后重新生成的可执行文件也可能不同。没有声称所有系统、所有升级
均能永久免授权。

## 本机通信

- 每次启动生成随机消息端口名和随机会话令牌，通过 Launch Services 参数传给组件。
- 组件仅接受版本及令牌匹配的请求，客户端同时校验版本、令牌与构建指纹。
- CFMessagePort 只在本机内存中传输：权限、连接、安全输入状态、活动标记、
  已确认的打字次数、打断标记与最近鼠标事件类别。
- 原始键码只在组件内存中由过滤器暂存，文字不读取，按键序列不保存，
  IPC 内容不落盘、不发送至网络。
- 客户端在串行后台队列发送带短超时的请求，不在动画主线程等待。
- 同一轮内最后一次快捷操作会清除之前的打字累计；后续新文字键可以重新确认。
- 拒绝授权或监听不可用时，不用聚合按键计数绕过过滤触发打字。

## 生命周期

- 暂停、睡眠、会话失活和熄屏时停止事件监听。
- 主应用显式退出时终止自己的组件实例。
- 收不到主应用心跳超过 3 秒先停止监听，超过 30 秒退出；主应用进程已退出
  时直接退出。恢复后自动启动、连接组件。
- 连接中断会清空动画节奏并自动恢复；系统授权弹窗可能阻塞组件，因此在等待
  授权时留出时间，不因短暂无响应立即关闭弹窗所属进程。
- 不安装 LaunchAgent，不新增独立登录项，不访问或重置 TCC 数据库。
